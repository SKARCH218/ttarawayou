# 실제 배포 구성 (2026-07-31 적용 완료)

sudo 비밀번호를 쓸 수 없어 **관리자 권한 없이** 배포했습니다. 계획(systemd 시스템 서비스 + nginx)과 다릅니다.

## 경로

```
사용자 → 공유기 80 → VPN서버 172.30.1.100:8081 → SSH터널 → node2 10.8.2.5:9090
                                                              └→ LLM 10.8.2.4:1234
```

**백엔드 jar 하나가 웹까지 서빙**하므로 프론트(3000)는 띄우지 않았습니다. 경로 분기가 없어 TCP 터널만으로 충분합니다.

## node2 (10.8.2.5) — 백엔드

| 항목 | 값 |
|---|---|
| 실행 | `~/trevit/start.sh` (JRE는 `~/jre21`, sudo 없이 홈에 설치) |
| 포트 | 9090 |
| 환경변수 | `~/trevit/trevit.env` (LLM 주소·타임아웃) |
| 로그 | `~/trevit/backend.log` |
| 자동 기동 | 사용자 crontab `@reboot` + 5분마다 헬스체크 후 재기동 |

```bash
# 상태 확인
ssh playlabs@10.8.2.5 'curl -s localhost:9090/api/wallet; tail -5 ~/trevit/backend.log'
# 재시작
ssh playlabs@10.8.2.5 'pkill -f trevit-api.jar; ~/trevit/start.sh > ~/trevit/backend.log 2>&1 &'
```

## VPN 서버 (172.30.1.100) — 터널

nginx는 sudo가 필요해 쓰지 못했고, **SSH 로컬 포워딩**을 systemd 사용자 서비스로 등록했습니다.

```bash
systemctl --user status trevit-forward     # 상태
systemctl --user restart trevit-forward    # 재시작
```

- 유닛: `~/.config/systemd/user/trevit-forward.service`
- `Restart=always` — 끊기면 5초 후 재연결
- VPN서버 → node2 는 SSH 키 인증으로 붙습니다

## 공유기에서 할 일

**외부 80 → `172.30.1.100:8081`** 포워딩 하나면 됩니다.

## 검증 기록

터널 경유로 플랜 생성 성공: `HTTP 200 · 84KB · 2일 일정 · aiReason 생성`

## 알려진 제약

- **HTTPS 없음** → 브라우저가 GPS를 막습니다. 데모 모드는 영향 없지만 실사용 시연은 불가.
  도메인을 잡고 `certbot`을 쓰려면 sudo가 필요합니다.
- **LLM은 현재 휴리스틱 폴백** — Gemma 26B 응답이 3분을 넘겨 타임아웃(25초)에 걸립니다.
  프롬프트 축소·`max_tokens` 제한으로 튜닝 필요.
- systemd 사용자 서비스는 로그인 세션에 묶입니다. 재부팅 후에도 유지하려면
  `sudo loginctl enable-linger user` 가 필요합니다(sudo 필요).
