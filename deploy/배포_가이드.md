# 트레빗 배포 가이드 (자체 서버 · VPN 구조)

## 구조

```
  User
   │  http(s)
   ▼
┌─ 집 112.166.208.166 ─────────┐        ┌─ 학교 180.81.34.214 ──────────────┐
│  공유기 80/443 포트포워딩      │        │  ※ 노드끼리 내부망 통신 불가         │
│         ▼                    │        │    → 각 서버에 VPN 설치, VPN IP 통신 │
│  VPN Server + nginx          │◀───────│  VPN Client                       │
│  (리버스 프록시)              │  터널   │    ├─ node1  10.8.2.4  LLM      │
└──────────────────────────────┘        │    └─ node2  10.8.2.5            │
                                        │         ├ frontend :3000          │
                                        │         └ backend  :8080  (로컬 통신) │
                                        └───────────────────────────────────┘
```

- 학교망은 포트포워딩이 안 되므로 **집 공인 IP를 입구로** 쓰고, VPN 터널로 학교 노드에 넘깁니다.
- node2 한 대에 프론트(3000)와 백엔드(8080)가 함께 뜨고 서로 로컬로 통신합니다.
- 백엔드는 플랜을 만들 때 `10.8.2.4:1234`(node1의 LM Studio)를 호출합니다.

### nginx 라우팅이 핵심입니다

브라우저는 프록시 뒤(80포트)에서 **같은 오리진으로 `/api`를 호출**합니다
(`js/common.js`: 3000·3030 포트로 직접 접속할 때만 `:8080`을 붙임).

| 경로 | 보낼 곳 |
|---|---|
| `/api/...` | `10.8.2.5:8080` (백엔드) |
| 그 외 | `10.8.2.5:3000` (프론트) |

> ⚠️ **`/api`를 프론트로 보내면 조용히 깨집니다.** Express 서버는 catch-all 라우트가 있어
> `/api/wallet` 요청에도 **200으로 index.html을 돌려줍니다.** 404가 아니라서 원인을 찾기 어렵습니다.
> `nginx-trevit.conf`는 `/api/`를 먼저 잡도록 돼 있으니 그대로 쓰세요.

## 1. node1 — LLM 서버 (10.8.2.4)

LM Studio에서 `google/gemma-4-26b-a4b-qat`를 로드하고 **서버를 0.0.0.0으로 개방**합니다.
(기본값 `127.0.0.1`이면 node2에서 접근할 수 없습니다.)

```bash
# node2에서 확인 — 모델 목록이 나와야 합니다
curl http://10.8.2.4:1234/v1/models
```

## 2. node2 — 백엔드 (10.8.2.5)

```bash
# ① jar 빌드 (개발 PC에서)
cd code/backend && ./gradlew bootJar
scp build/libs/trevit-api-0.0.1-SNAPSHOT.jar trevit@10.8.2.5:/opt/trevit/trevit-api.jar

# ② 서버 준비 (node2에서)
sudo useradd -r -s /bin/false trevit
sudo mkdir -p /opt/trevit && sudo chown trevit:trevit /opt/trevit
sudo apt install -y openjdk-21-jre-headless

# ③ 환경 변수
sudo cp .env.production.example /opt/trevit/trevit.env
sudo nano /opt/trevit/trevit.env        # LMSTUDIO_BASE_URL 등 확인
sudo chown trevit:trevit /opt/trevit/trevit.env && sudo chmod 600 /opt/trevit/trevit.env

# ④ 서비스 등록
sudo cp trevit-backend.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now trevit-backend
curl http://localhost:8080/api/wallet    # {"balance":500000} 이면 성공

# ⑤ 프론트(3000) — 같은 node2에서 함께 띄웁니다
cd /opt/trevit/frontend && npm ci --omit=dev && node server.js
curl http://localhost:3000/              # 200 이면 성공
```

프론트도 자동 재시작이 필요하면 `trevit-backend.service`를 복사해
`ExecStart=/usr/bin/node /opt/trevit/frontend/server.js` 로 바꿔 등록하시면 됩니다.

## 3. 집 VPN 서버 — 리버스 프록시

```bash
sudo apt install -y nginx
sudo cp nginx-trevit.conf /etc/nginx/sites-available/trevit
sudo ln -s /etc/nginx/sites-available/trevit /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# 공유기에서 80(가능하면 443도) → 이 서버로 포트포워딩
curl http://112.166.208.166/api/wallet    # 밖에서도 되는지 확인
```

## 4. 반드시 짚고 갈 것

### HTTPS가 없으면 위치 기능이 막힙니다

브라우저는 **HTTPS 또는 localhost가 아니면 `geolocation`을 차단**합니다.
`http://112.166.208.166` 로 접속하면 실제 GPS 따라가기가 동작하지 않습니다.

- 심사·시연은 **데모 모드**(GPS 불필요)로 커버되므로 당장 막히지는 않습니다.
- 그래도 실사용 시연을 하려면 HTTPS가 필요합니다. 도메인을 하나 잡고:
  ```bash
  sudo certbot --nginx -d <도메인>
  ```
  무료 도메인은 DuckDNS(`*.duckdns.org`) 같은 DDNS로도 충분합니다.

### 심사 기간 내내 살아 있어야 합니다

1차 심사가 **8/1~8/17**입니다. 이 구조는 **집 인터넷 + 학교 네트워크 + VPN** 셋이 모두 살아 있어야 동작합니다.

- 방학 중 학교 네트워크·전원 정책을 확인하세요. 밤이나 주말에 끊기면 심사위원이 접속하지 못합니다.
- 집 공인 IP가 유동이면 바뀔 수 있습니다 → DDNS를 걸어 두세요.
- https://uptimerobot.com 에 `/api/wallet`을 5분 간격으로 등록해 두면 죽었을 때 바로 알 수 있습니다.

### node1(LLM)이 죽어도 서비스는 삽니다 — 검증 완료

LLM 주소를 도달 불가 상태(`10.8.2.4` 미기동)로 두고 플랜을 요청한 결과:

```
LM Studio 호출 실패(Connect timed out) → 휴리스틱 폴백
HTTP 200 · 7.3초 · plannedBy=ALGORITHM · aiReason 생성됨
```

VPN이 끊기거나 node1이 꺼져도 **node2만 살아 있으면 심사위원은 정상적으로 플랜을 받습니다.**
다만 화면에 "AI가 설계한 플랜" 대신 "알고리즘이 설계한 플랜"으로 표시되므로,
심사 기간에는 node1을 되도록 켜 두는 편이 유리합니다.

### 더 단순한 대안 (구조를 크게 바꾸지 않음)

노드 간 통신용 VPN은 그대로 두고, **바깥 입구만 Cloudflare Tunnel로** 바꾸는 방법이 있습니다.

```bash
# node2에서
cloudflared tunnel --url http://localhost:8080
```

- 포트포워딩·공인 IP·집 서버가 필요 없고, **HTTPS가 자동**이라 GPS 문제도 사라집니다.
- 학교 방화벽 뒤에서도 나가는 연결만 쓰므로 대부분 통과합니다.
- 무료 계정 + 도메인 연결 시 고정 주소도 가능합니다.

지금 구조를 유지하실 거면 위 1~3단계 그대로 진행하시고, 이 방법은 **HTTPS가 급할 때 대안**으로 기억해 두세요.
