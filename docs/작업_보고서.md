> 결과: **6개 커밋으로 OGQ 브랜치에 푸시 완료.** 남은 일은 [아침_체크리스트.md](아침_체크리스트.md) 4개.

## 1. 무엇이 바뀌었나

### 리브랜딩
따라와유 → **트레빗(Trevit)**. 웹·앱·문서·패키지명(`com.trevit`)·저장소 키까지 전부 반영.

### 백엔드 — Java Spring → Kotlin Spring Boot
- Maven/Java → Gradle(Kotlin DSL)/Kotlin 전면 포팅, REST 계약은 그대로 유지
- **프로필 기반 계획 수립**: 성별·연령대·MBTI·목적·음식 취향·선호 키워드·걷기 최소화
  ·자유 서술 **취향 메모**를 받아 LLM 프롬프트와 휴리스틱 양쪽에 반영
- **AI 추천 이유(`aiReason`)** 응답 추가 — LLM이 생성, 폴백 시 규칙 기반 문장 생성
- **서비스 지역을 수도권으로 제한**: 서울·경기·인천 21곳(별칭 포함). 수도권 밖 좌표는 서울로 폴백
- 단일 jar가 웹 데모까지 서빙 → 배포 대상이 하나

### 앱 — Jetpack Compose (Kotlin Multiplatform)
- `shared`(DTO·Ktor 클라이언트·도메인, iOS 공유) + `composeApp`(Android)
- 홈 → 여행 설정 → 프로필 → 생성 → 결과 → 여정, Material3 관용구로 구성
- 디자인 시스템 적용: 토스페이스 이모지 폰트, 아이콘 PNG(Material Icons 대체)
- APK 빌드 성공: `code/app-kmp/composeApp/build/outputs/apk/debug/composeApp-debug.apk`

### 웹 데모 (심사위원 체험용)
- 입력 폼을 기획서대로 확장(지역·목적·예산·기간·인원·음식·키워드·걷기·취향 메모·성별·연령·MBTI)
- **데모 모드**: GPS 없이 경로를 자동 이동(1/3/8배속) → 도착 리빌 → 다음 장소
- 장식용 이모지 제거, 안내 문구 축약

## 2. 발견해서 고친 문제들

밤 사이 실제로 돌려보며 잡은 것들입니다. **모두 배포 후 심사에서 드러날 문제였습니다.**

| # | 문제 | 영향 | 조치 |
|---|---|---|---|
| 1 | **API 키가 커밋 직전 상태였음** (`run-backend.sh`에 TMAP·TAGO·ODsay 실키) | 공개 저장소 유출 + 윤리·안전 P/F 탈락 위험 | `.env`(git 제외)로 분리, 스크립트 템플릿화. 과거 히스토리도 검사 — 유출 없음 확인 |
| 2 | **OSM 공식 타일 서버가 차단**("Access blocked") | 지도가 깨져 보임 — 데모의 핵심 화면 | CARTO Positron으로 교체(무료·키 불필요), 실패 시 안내 폴백 |
| 3 | **지도가 아예 렌더링 안 됨** (TMAP SDK에 플레이스홀더 키) | 여정 화면 작동 불가 | Leaflet + OSM 계열로 전환, 키 의존 제거 |
| 4 | **데모가 도착 판정 없이 멈춤** | 시연이 중간에 정지 — 심사 중 최악 | 경로가 목적지보다 짧게 끝나면 직선 보간으로 이어가고, 경로 교체 시 재동기화, 경로 소진 시 도착 확정 |
| 5 | **예산 초과 플랜 생성**(300,000 예산에 318,600 총비용) | "남는 예산 −18,600" 표시 | 숙박비 초과분을 관광·식비에서 비례 차감. 시드에 저가 숙소 보강 |
| 6 | **디자인 시스템 478개 파일이 0바이트**로 깨져 있었음 | 아이콘·폰트 사용 불가 | 원본으로 전체 복구 |
| 7 | TMAP 쿼터 초과(429) 시 플랜 생성 실패 | 키가 있어도 데모 중단 | 수도권 시드 데이터 폴백 — **키 없이도 전체 플로우 동작** |
| 8 | LLM 응답 대기가 최대 5분 | 시연 중 무한 대기 | 20초 타임아웃 후 휴리스틱 폴백(`LMSTUDIO_TIMEOUT_MS`) |
| 9 | 앱 빌드가 JDK 26에서 실패 | 빌드 불가 | JDK 21로 고정(`org.gradle.java.home`) |
| 10 | **토스페이스 폰트를 전체 글꼴에 적용해 숫자 자간이 벌어짐**("3 0 0 , 0 0 0 원") | 앱·웹 전 화면의 금액 표시가 조잡해 보임 | 웹은 `unicode-range`로 이모지에만, 앱은 이모지 Text에만 직접 지정 |

## 3. 검증한 것 (증거)

- **백엔드**: 키 전무 + LLM 끔 상태로 수도권 7개 지역(서울·인천·수원·가평·파주·용인·강화·안산)
  플랜 생성 — 전부 HTTP 200, **응답 5초 내**, 예산 초과 없음, 걷기 최소화 시 산·등산 장소 제외 확인
- **웹 E2E**(단일 jar 배포 경로 `:8081`): 입력 → 플랜(예산 234,500 / 300,000) →
  데모 모드로 **Day 1·Day 2 완주**(도착 리빌 → 다음 일차 해금)까지 브라우저로 확인
- **앱**: APK 빌드 성공 + **Pixel 3a 에뮬레이터 실동작 검증** —
  홈 → 여행 설정(서울) → 프로필(10대·INFP·한식·걷기 최소화·공원·취향 메모)
  → 플랜 생성(총비용 202,000 / 예산 300,000, AI 추천 이유 표시)
  → 여정(OSRM 실도로 경로 + 비공개 `?` 마커) → 10배속 시뮬레이션
  → 도착 공개("인사동 쌈지길 · 관광지 · ★4.2")까지 전 구간 정상. 화면은 `docs/screenshots/`
- **정적 자산**: 배포 jar에서 토스페이스 폰트·디자인 시스템 아이콘 200 응답 확인
